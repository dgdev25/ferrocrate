# S23 — build: a 1 GiB layer cap rejects ordinary application images
- apps: actix-basics, docker-todo, gin-basic · step: build · class: product · status: open · first seen: 2026-08-27
- command: `ferro-cli build -t bench/docker-todo:latest .`
- Docker: builds. Ferrocrate: `error: layer size exceeds maximum (1298423296 bytes)`.
- cause: `ferro-core/src/dockerfile_build.rs` assembled the layer in memory and capped it at 1 GiB to bound peak memory. A node_modules-heavy application image passes that in normal use.
- partial fix: the cap is now four gibibytes and `FERROCRATE_MAX_LAYER_BYTES` overrides it. This unblocks the app but keeps a cap that Docker does not have.
- remaining: stream the layer to a temporary file instead of holding it in memory, then remove the cap. Test: build an image whose context exceeds the cap and assert it succeeds with bounded resident memory.
- impact: the build failure cascades. Each of the three apps recorded 33 failures behind it, about 99 of the run's total. Observed layer sizes: 1.20 GB (gin-basic), 1.30 GB (docker-todo), 1.49 GB (actix-basics).
