# S36 — daemon: image inspect emits Created as a JSON number, so every docker image inspect of a pulled image fails client-side
- suite: moby-integration (contributes to the blocked pre-seed; also breaks any test or CLI step that inspects an image) · class: product · status: open · first seen: 2026-08-27
- command: `GET /v1.43/images/{name}/json` for an image in the store, then `docker image inspect <name>` (CLI).
- Docker: `Created` is an RFC 3339 string, e.g. `"2026-08-27T10:35:10.000000000Z"`.
- Ferrocrate: `Created` is a JSON number: `"Created":1787829310`. Observed 2026-08-27 on images pulled through the compat API (tag and digest pulls alike).
- cause: the inspect serializer writes the Unix timestamp directly instead of formatting it as a string. The Docker API type is `string`; the Go CLI unmarshal fails: `json: cannot unmarshal number into Go struct field ImageInspectResult.InspectResponse.Created of type string`.
- scope: the image inspect response in the Docker-compat server (and any other endpoint embedding Created — history, image list fields). Every `docker image inspect` against Ferrocrate fails, which also breaks client-side steps that inspect before tagging or running.
- test: pull `busybox:latest` (raw API), then `curl --unix-socket <sock> .../images/busybox:latest/json` must return `"Created":"<RFC3339>"` (string), and `docker image inspect busybox:latest` must succeed.
