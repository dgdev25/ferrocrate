# S13 — CI regression: `create` succeeds but `containers --all --format json` returns an empty list
- source: CI (ferro-lab-linux runner) · step: Unit gates / apps/ferro-desktop-ui/src/forgeShell.test.mjs:164 · class: product · status: closed · first seen: 2026-08-26
- test: "release ferro-cli Docker list output decodes into actionable desktop rows"
- failure: `create --name desktop-contract busybox true` exits 0, then `containers --all --format json` prints `[]`; the assertion `row` fails with `daemon exit=running; stderr=(none); list stdout=[]`.
- regression window: CI green at 24b6529d (13:39), red at 65063708 (18:21) and on rerun. Introduced by one of the ten fixes merged in 88a07026 (S1–S9).
- prime suspects: `8cf784d2 fix(system): prune orphaned runtime directories` (a startup or background reap may delete the just-created container's record when the state dir looks orphaned) and `fcf62393 fix(cli): accept Docker grouped verb aliases` (list routing).
- does not reproduce on the same host outside CI: `bash /path/to/ferrocrate-lab/repro-ci-test.sh <binary>` creates the container and lists it correctly with an isolated HOME, XDG_RUNTIME_DIR, FERROCRATE_HOME and socket. The CI job runs under the actions-runner service environment, so the difference is environmental (likely env vars or timing).
- cause: `8cf784d2` was not an automatic reaper; it only added the explicit local `system prune --orphans` operation. The actual fresh-state race was daemon ownership being published after the socket bind but before runtime/store initialization and startup reconciliation completed. A native client could then observe the owner and initialize independently against the same state.
- fix: daemon ownership is now published only after reconciliation and every request store is ready (`b8d8eb60`). The Docker-compat integration suite covers create-then-list on a fresh daemon state (`docker_api_create_then_list_keeps_the_fresh_container_record`); the core helper reaper test proves a durable container record protects its helper (`slirp_reaper_leaves_a_recorded_container_helper_alone`).
- passing evidence: `cargo test --workspace` passed; `scripts/verify-no-warnings.sh` passed; `node --test src/forgeShell.test.mjs` passed 23/23, including the release create-then-list desktop contract; classic Docker conformance passed 85/85 and BuildKit-default passed 85/85 on 2026-08-26.
