# S131 — `GET /containers/json`: an empty host port (`":80/tcp"`) fails the whole listing

- suite: compose-e2e · class: product defect (compat contract) · status: closed · first seen: 2026-08-28
- retest: 2026-08-28T07:47Z uncontended run at the S131 fix (`bench/results/2026-08-28/suite-compose-e2e-ferrocrate.jsonl`, 147 records). Zero hits for `invalid host port` in the whole run; the build-test and volume-test sessions completed instead of failing every later step. The host-port-at-start gap stays open in this ticket's fix note.
- command: any `docker ps` / `GET /containers/json?all=1` after compose creates a service that publishes a container port without a host port (fixtures: `build-test` nginx, `volume-test` nginx); repro: create with `{"HostConfig":{"PortBindings":{"80/tcp":[{"HostPort":""}]}}}` then `docker ps -a`
- required contract: Docker stores `HostPort: ""` as an ephemeral binding and assigns the host port at start. Before start, the port appears in `/containers/json` as `{"PrivatePort":80,"Type":"tcp"}` with no `IP` and no `PublicPort`. A listing never fails because of one stored record.
- impact: total for any session that created such a container. `docker_pending_list_entry` ran `parse_publish(&spec.publish)?` inside the listing's `Result` collect, `parse_publish` rejected the empty host part with `run: invalid host port`, and the handler turned that into a 500 for the whole listing. compose lists containers to decide what to stop, remove and restart, so every later step of the affected projects failed. `/path/to/ferrocrate-lab/runtimes/compose-clean/docker-pending.json` held two such specs (`build-test-nginx-1`, `compose-e2e-volume-nginx-1`) at the time of the 2026-08-28 run.
- fix: `parse_publish` (ferro-cli/src/main.rs) accepts an empty host part as the ephemeral sentinel (`host_port: 0`); `docker_port_summaries` omits `IP` and `PublicPort` for host port 0, matching Docker's unassigned-binding shape; the `/containers/json` handler skips a pending spec it cannot render instead of failing the listing; `validate_port_mapping_conflicts` (ferro-core/src/runtime.rs) skips host port 0 in both compared sides, since an ephemeral mapping claims no fixed host port. Start-time ephemeral port assignment is still missing: `configure_slirp_host_forwards` cannot express "assign a port", so `docker run -p 80` / `-P` cannot expose the container until the daemon picks a host port at start. That is the remaining gap in this ticket.
- regression tests: `parses_publish_mappings` (ephemeral case), `port_summaries_omit_the_binding_until_a_host_port_exists`, `ephemeral_port_mappings_do_not_conflict`, `docker_listing_survives_a_pending_spec_with_an_empty_host_port` (create → daemon restart → list).
