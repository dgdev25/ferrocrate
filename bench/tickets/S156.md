# S156 — BuildKit session file-sync does not implement the bidirectional transfer protocol
- suite: buildkit-dockerfile (at least 35 direct product failures across tar/HTTP/Git contexts, target/outline queries, and excluded-file cases) · class: product · status: closed · first seen: 2026-08-28
- command: `GO_TEST_TIMEOUT=0 SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh buildkit-dockerfile --engine ferrocrate`.
- Docker: client frontends may upload local, tar, Git, and remote Dockerfile contexts over BuildKit's FileSync session and then complete the stream cleanly. Ferrocrate: solves report `buildkit session: FileSync.DiffCopy was not exposed`, `buildkit filesync: client disconnected before FIN`, `buildkit filesync: symlinks are not supported`, or a cancelled/RST stream. The fresh run retains these in `TestTarContext`, `TestHTTPDockerfile`, `TestDockerfileFromGitSHA*`, `TestTargets*`, `TestOutline*`, and `TestExcludedFilesOnCopy`.
- cause: the embedded BuildKit session bridge exposes only a partial FileSync surface and does not preserve the protocol's copy/half-close lifecycle. The varied contexts are consumers of that one session channel, not independent Dockerfile parser failures.
- scope: any BuildKit client frontend or Dockerfile solve whose local inputs require file synchronization, including remote Dockerfiles, tar contexts, target/outline inspection, and symlink-bearing filtered contexts.
- test: drive a client solve with a tar context and a client-frontend outline request; assert that `DiffCopy` is available, the sender FIN is accepted, and a symlink in an excluded context is represented without resetting the stream.
- evidence: full harness log `/tmp/suite-buildkit-dockerfile.1DdXkt/go.json` from the recorded 813228f8 run (the JSONL tails retain only the later sandbox teardown for many of these cases).

Closed 2026-08-30: FileSync now keeps its gRPC request side open after the
receiver's protocol `FIN`, waits for the sender's reciprocal `FIN`, and only
then completes. The regression covers the actual stat/request/data/FIN flow,
including a relative symlink; it failed before the change because the h2 stream
was reset before the sender could acknowledge the transfer.
