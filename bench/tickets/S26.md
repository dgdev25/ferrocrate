# S26 — build: stage layers grew about threefold after the S15-S22 merge
- apps: actix-basics, gin-basic · step: build · class: product · status: open · first seen: 2026-08-27
- measured: the same builds, same contexts, same day.
  - actix-basics: 1.49 GB before the merge, 4.44 GB after.
  - gin-basic: 1.20 GB before, 4.45 GB after.
- Two different language stacks now produce layers within 2 MB of each other, which points at shared content rather than application output. A Gin hello-world has no legitimate reason to emit four gibibytes.
- context is not the cause: the actix context is 6.4 MB and its `.dockerignore` excludes `.git` and `target`, which the bench confirms are absent.
- suspects, in order: `70de6dba` provides `/dev` inside rootless Bubblewrap RUN stages, and the layer walk may now descend into mounted trees; `260b8c9e` changed `COPY . .` placement; the named-stage work in `5210a0b7` may have changed which parent the layer diffs against, so a stage records the whole filesystem rather than its change set.
- reproduce: build `FROM golang:1.23` plus `RUN true` and compare the layer size against `docker build` of the same file. A correct stage layer holds the change set, not the rootfs.
- impact: masks the real state of two apps. It also defeats S23's raised cap, so those builds still fail.
