# S171 — classic builder: `docker build: invalid tar entry: numeric field did not have utf-8 text`

- suite: compose-e2e · class: product defect · status: closed · first seen: 2026-08-28
- command: `DOCKER_BUILDKIT=0 docker compose build` / `up --build` (all 8 `TestLocalComposeBuild/DOCKER_BUILDKIT=0_*` subtests)
- Docker: builds the same context with the legacy builder and exits 0.
- Ferrocrate: exit 1, `docker build: invalid tar entry: numeric field did not have utf-8 text: '<binary>' when getting cksum for <binary>` — the builder's tar reader is handed bytes that are not the tar stream (or is re-reading a stream already consumed), so a numeric header field contains payload bytes.
- impact: 8 failures; the whole classic-builder path of compose `build` is unusable, which blocks every `DOCKER_BUILDKIT=0` scenario.
- regression tests: a unit test that feeds a small valid tar to the builder's entry reader and asserts no error; an integration test running the classic builder over the compose `build-test` fixture.

Fix: detect and decode gzip-compressed legacy `/build` contexts before reading tar entries; the `build-test` Compose fixture now completes with `DOCKER_BUILDKIT=0`.
