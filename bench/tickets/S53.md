# S53 — volume: `volume create` on an existing name errors, docker is idempotent
- apps: all · step: volume-create · class: product · status: open · first seen: 2026-08-27
- command: `volume create fzv-<tag>` twice (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `volume create fzv-<tag>`, `volume create fzv-<tag>`)
- Docker: exit 0 both times; prints the name and reuses the existing volume. `docker volume create` is documented as idempotent.
- Ferrocrate: first create succeeds; second exits 1 with `error: volume already exists: fzv-<tag>`. The volume itself is still usable.
- cause: the create path treats an existing name as an error instead of returning the existing volume.
- scope: every compose-style bootstrap script that creates named volumes unconditionally; retry logic that treats a nonzero exit as fatal.
- test: create a volume, create it again, assert exit 0 both times and that `volume ls` lists one volume.
