# S92 — build: relative bind-mount targets in `RUN --mount` are rejected
- app: kutt · steps: `compose-up`, `compose-health` · class: product · status: closed · first seen: 2026-08-27
- command: build `/data/dev/bench-apps/kutt/Dockerfile`, whose `RUN --mount=type=bind,source=package.json,target=package.json` uses a target relative to `WORKDIR` (its cache target is absolute).
- Docker: builds the service. Ferrocrate: `invalid Dockerfile: cache mount target must be an absolute non-parent path`.
- cause: mount-target validation rejects the relative bind targets, then reports the generic cache-mount error. Docker/BuildKit resolves a relative `target` against the current workdir for these `RUN --mount` forms.
- impact: Compose cannot build Kutt; the following health check fails as a consequence.
- fix: retain traversal protection but resolve relative bind/cache targets against the stage workdir before validation. Cover relative bind targets, relative cache targets, and an escaping `../` rejection.

## Fix
`RUN --mount` now resolves relative bind and cache targets against the current stage `WORKDIR` before mount setup. Parent traversal remains rejected; default cache identities are deterministic hashes of their resolved target so nested paths remain valid cache keys.

## Verification
On 2026-08-28, a Docker build using `WORKDIR /usr/src/app` and `RUN --mount=type=bind,source=package.json,target=package.json test -f package.json` exited 0. Focused regression `cargo test -p ferro-core run_mount_targets_resolve_relative_to_workdir_without_parent_traversal -- --nocapture` passed, covering relative bind and cache targets plus `../` rejection.
