# S90 — rootless networking: slirp4netns API socket path exceeds `SUN_LEN`
- apps: actix-basics, battleships, flask-tutorial, gin-basic, node-getting-started, spring-petclinic, uptime-kuma · steps: `run-detached`, `compose-up`, `err-port-in-use` · class: product · status: closed · first seen: 2026-08-27
- command: use `FERROCRATE_HOME=/path/to/ferrocrate-lab/runtimes/apptriage` and run an image or Compose service needing rootless slirp networking.
- Docker: starts the container. Ferrocrate: `network error: slirp4netns API socket did not become ready: path must be shorter than SUN_LEN`.
- cause: the slirp4netns API socket is derived under the configured runtime/store path without bounding the Unix-domain socket pathname to the platform `sun_path` limit. The required isolated runtime path is valid, but its appended container/network components are too long.
- impact: this single root failure prevents each affected detached run and cascades into health, copy, lifecycle, commit/export, image-removal and Compose checks (at least 84 product failures in the 19:10Z–19:50Z rerun).
- fix: put slirp API sockets in a short per-user runtime directory, or derive a deterministic short hashed pathname/symlink, while retaining collision isolation and cleanup. Test with a deliberately long `FERROCRATE_HOME` and a published-port `run -d` plus Compose service.

## Fix
Rootless slirp API sockets now live under a private short per-user temporary runtime directory. Their filenames are deterministic hashes of the container ID, preventing collisions without inheriting the configured store path length. The orphan helper reaper recognizes the new ownership paths.

## Verification
On 2026-08-28, binding a deliberately overlong AF_UNIX pathname failed with `AF_UNIX path too long`, confirming the host limit behind the reported slirp failure. Focused regression `cargo test -p ferro-core slirp_api_socket_stays_within_unix_socket_limit_for_long_runtime_paths -- --nocapture` passed, proving the generated sockets stay below 108 bytes and do not collide for distinct container IDs.
