# S21 — rootless custom networks are unsupported (parity gap, not just a boundary)
- source: real-app bench · apps: docker-flask, fastapi-fullstack, kutt, microblog, uptime-kuma, docker-todo · step: network-create · class: product · status: open · first seen: 2026-08-26
- `ferro-cli network create x` as a normal user → `custom networks need rootful mode` (the clearer message from S7).
- Docker rootless creates user-defined networks, so this is a capability gap rather than a documented boundary. It caused 13 direct failures plus 29 cascading ones (`network-run`, `network-rm`, and every compose app that needs a project network).
- decision needed: implement user-defined networks on the rootless path (slirp4netns or a userspace bridge, as Docker rootless does), or declare the gap in docs/FEATURE-MATRIX.md and mark these bench steps as boundaries. S7 only improved the wording; the capability is still absent.
- recommendation: implement it. Six of fourteen bench apps and most compose workloads need a project network.
