# S191 — `cp` rejects named-volume targets and ignores renamed host destinations

- apps: Battleships pilot and any container with a persisted mount · step: `cp` in/out · class: product · status: closed · first seen: 2026-08-28
- commands: `ferro-cli cp README.md container:/app/data/README-probe.md` and `ferro-cli cp container:/app/README-probe.md /tmp/battleships-README-probe.md`.
- Docker: permits archive uploads into writable named volumes and bind mounts, and creates the exact requested host destination filename.
- Ferrocrate: rejected every persisted-mount archive target with `archive target is a persisted mount target`; outbound extraction unpacked beside a missing destination, allowing the tar's source basename to replace the requested basename.
- cause: `ContainerRuntime::put_archive_options` treated all persisted mounts as forbidden boundaries instead of resolving the longest matching mount to its durable source. The direct CLI outbound path used `tar::Archive::unpack(parent)` for every missing/non-directory target and never renamed the archive root to the requested destination.

## Fix

Archive reads and writes now resolve named-volume and bind targets to the canonical persisted source boundary, reject read-only and tmpfs writes, select the longest matching mount, and retain canonical containment plus the existing sanitized archive extraction path. Host extraction stages the validated tar under the canonical destination parent and installs its single top-level entry at the exact requested name; symlinked destination components are rejected.

## Verification
