# S48 — run: `diff` reports /etc/resolv.conf as added on a fresh container
- apps: all · step: diff · class: product · status: open · first seen: 2026-08-27
- command: `diff <name>` on a container just started, before any file inside it was touched (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `diff fz-<tag>`)
- Docker: exit 0, no output — no filesystem changes relative to the image. Runtime-injected files (/etc/resolv.conf, /etc/hostname, /etc/hosts) are excluded from the change set.
- Ferrocrate: exit 0, `A etc/resolv.conf` — the runtime-injected resolver file counts as an added file. The path is also printed without the leading slash docker uses (`A /etc/...`).
- cause: the diff implementation compares the container rootfs against the image without excluding the files the runtime itself mounts or writes.
- scope: any CI step that asserts a clean diff after deploy (image drift detection) fails on every container. The leading-slash format difference breaks parsers regardless.
- test: start a fresh container, `diff`; assert empty output and exit 0. Write a file inside, `diff`; assert exactly `C /path` for it.
