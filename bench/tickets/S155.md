# S155 — compose build: a pruned base image is not pulled when required
- app: kutt · steps: `compose-up`, `compose-health` · class: product · status: open · first seen: 2026-08-28
- command: run the standard matrix through `image prune -f`, then `cd /data/dev/bench-apps/kutt && ferro-cli compose up -d --build`.
- Docker: rebuilds the service, pulling `node:22-alpine` if it is not locally present.
- Ferrocrate: exits 1 with `invalid Dockerfile: base image not found: node:22-alpine`.
- cause: the Compose build path resolves `FROM` only against the local store after the matrix prune instead of acquiring the missing base image.
- scope: any Compose build whose base has been pruned or has not been pre-pulled; the failure prevents both image construction and service health.
- test: remove a known base from the local store, build `FROM alpine:3.20`, and assert the builder pulls it and completes; cover the same path through `compose up --build`.
- proof: current-main 14-app matrix with `FERROCRATE_BIN=/data/dev/ferrocrate-app-retriage2/target/release/ferro-cli`, `bench/results/2026-08-28/kutt-ferrocrate.jsonl`.
