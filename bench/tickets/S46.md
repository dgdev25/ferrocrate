# S46 — run: `rm -f` on a missing container fails instead of being a no-op
- apps: all · step: rm-force · class: product · status: closed (96e76c57) · first seen: 2026-08-27
- command: `rm -f <name>` where no container with that name exists (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `rename fz-<tag> fz-<tag>-r`, `rm -f fz-<tag>`)
- Docker: exit 0, no output. With `--force`, removing a missing container is a successful no-op; without `--force` it errors.
- Ferrocrate: exit 1, `rm: fz-<tag>: container not found`. The force flag is accepted but the not-found path still errors.
- cause: the forced removal path checks existence and fails before reaching the removal, instead of treating absence as already-removed.
- scope: every cleanup script that runs `rm -f` defensively (idempotent teardown, CI between steps). This is the most common shape of docker rm usage.
- test: `rm -f` a name that was never created; assert exit 0 and no stderr. Also assert plain `rm` of a missing name still fails, and `rm -f` of an existing running container still kills and removes it.
