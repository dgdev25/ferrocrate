# S45 — cli: `stop -t` and `kill -s` short flags are rejected
- apps: all · step: stop · class: product · status: closed (650199ad) · first seen: 2026-08-27
- command: `docker stop -t 1 fz-<tag>` and `docker kill -s TERM fz-<tag>`
- Docker: exit 0; `-t` is the documented short form of `--timeout`, `-s` of `--signal`.
- Ferrocrate: exit 2, `error: unexpected argument '-t'` (and `-s`); only the long forms exist.
- cause: the clap argument definitions declare long flags without the short aliases Docker documents.
- scope: every script written against docker's documented CLI surface. Found by direct inspection while probing the CLI for the fuzzer grammar; the fuzzer itself uses the long forms so it can exercise the operations.
- test: `stop -t 1` and `kill -s TERM` on a running container; assert exit 0 for both, and that the flags take effect: a container killed with `-s TERM` reports exit code 143, not 137.
- note: audit other documented short flags while fixing (`-v` on rm, `-a` on ps, `-q`, `-f` on rmi and rm all work today).
