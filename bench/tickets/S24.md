# S24 — build: the image config does not inherit from the base image
- apps: mdn-static (26 failures behind it) · step: run-detached · class: product · status: fixed pending bench verification · first seen: 2026-08-27
- command: build a Dockerfile that sets no `CMD`, then `ferro-cli run -d <image>`
- Docker: runs, using the base image's `Cmd`. Ferrocrate: `error: command is required to run container`.
- cause: a build stage starts with `entrypoint: None, cmd: None` (`ferro-core/src/dockerfile_build.rs`, stage construction) and nothing reads the base image's config. A Dockerfile that adds only `COPY` therefore produces an image with no command at all. S17 made `run` use the image's command; there is no command to use.
- scope: `Env` is already inherited by `a8560a3a`, through `load_base_environment` and `BaseImageInfo`. The same path must carry `Cmd`, `Entrypoint`, `WorkingDir`, `User`, `ExposedPorts`, `Volumes`, `StopSignal` and `Labels`, with the Dockerfile's own instructions overriding what it sets. Docker's rule: a stage that sets `ENTRYPOINT` clears the inherited `Cmd` unless it also sets `CMD`.
- test: build `FROM nginx:1.27-alpine` plus one `COPY`, then assert `image inspect` reports the base's `Cmd` and that `run -d` starts without an explicit command.

## Fix
`BaseImageInfo` now carries a `BaseConfig` read by `load_base_config`, and the final image config inherits `Cmd`, `Entrypoint`, `WorkingDir`, `User`, `StopSignal`, `ExposedPorts`, `Volumes` and `Labels` where the Dockerfile sets none. The environment is composed with the same `stage_environment` the RUN steps use, so the built image also carries the base's PATH, which it did not before.

Docker's entrypoint rule is a pure function, `inherited_command`, with a test covering all four combinations. `merge_unique` has its own test. Both pass.
