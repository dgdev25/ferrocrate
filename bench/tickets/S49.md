# S49 — image: `image prune` removes tagged images, docker prunes dangling only
- apps: all · step: image-prune · class: product · status: closed (efe45068) · first seen: 2026-08-27
- command: `image-prune --force` after committing a container to a tagged image (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `commit fz-<tag> fzimg-<tag>:latest`, `image prune -f`)
- Docker: `docker image prune -f` removes only dangling images (untagged, `<none>:<none>`). A tagged image like `fzimg-<tag>:latest` survives; output `Total reclaimed space: 0B`.
- Ferrocrate: removes the tagged image too (`image prune: removed=2`, and `images` no longer lists it). Unfiltered ferro prune behaved like `docker image prune -a`.
- cause: the prune matcher treated a missing `dangling` selector as "remove everything", and the CLI rejected the `label`/`label!` selectors Docker accepts, so the fuzzer's scoped prune could not be expressed at all.
- scope: any script that commits an image and then prunes, expecting the commit to survive — the standard build-and-clean pattern.
- test: commit a container to a tag, run `image prune --force`, assert the tagged image is still listed and only dangling layers were removed.
- seed: `bench/fuzz/seeds/20260827-image-prune-*.json`

## Fix
`docker_image_prune_matches_filters` now defaults to dangling-only when no `dangling` selector is present; `dangling=false` selects every unused reference. `image prune` and `image image prune` gain `-a/--all`, which maps to `dangling=false` on the direct path and in the remote client. `validate_docker_image_prune_filters` accepts `label` and `label!`; ferro image records carry no labels, so a positive selector removes nothing, the same result Docker gives on an unlabelled store. `system prune` keeps tagged images and runs one `dangling=false` pass with `-a` instead of two. The bench adapter no longer drops `image prune` filters.

## Verification
Verified 2026-08-27 in the isolated fuzz runtime: commit a running container to `fzimg-s49y:latest`, `image prune -f` gives `removed=0` and `images` still lists the commit; `image prune -a -f` removes the commit and keeps the base the container still references. `--filter label=fz-s49y` is accepted and removes nothing. Regression test `image_prune_default_removes_dangling_images_only` covers default, label, and `-a` paths.
