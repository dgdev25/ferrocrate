# S154 — build: Dockerfile `# syntax=` directives are rejected
- app: gitea · step: `build` · class: product · status: open · first seen: 2026-08-28
- command: `cd /data/dev/bench-apps/gitea && ferro-cli build -t bench/gitea:latest .`.
- Docker: accepts the leading `# syntax=docker/dockerfile:1` directive and builds the image.
- Ferrocrate: exits 1 with `unsupported Dockerfile instruction: Dockerfile syntax directive is not supported: docker/dockerfile:1`.
- cause: the Dockerfile parser treats the BuildKit syntax directive as an unsupported instruction instead of consuming the standard leading parser directive.
- scope: Dockerfiles using the widely deployed `docker/dockerfile:1` frontend selector; the initial build failure cascades into the image and lifecycle matrix steps.
- test: build a minimal Dockerfile beginning with `# syntax=docker/dockerfile:1` and `FROM alpine`; assert the directive is accepted and does not become an image instruction.
- proof: current-main 14-app matrix with `FERROCRATE_BIN=/data/dev/ferrocrate-app-retriage2/target/release/ferro-cli`, `bench/results/2026-08-28/gitea-ferrocrate.jsonl`.
