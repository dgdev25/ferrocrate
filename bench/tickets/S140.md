# S140 — BuildKit control connection closes before the HTTP/2 server preface
- suite: buildkit-dockerfile (at least 240 direct product failures; the same control failure also interrupts 747 records) · class: product · status: closed (68a673fa) · first seen: 2026-08-27
- command: `SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh buildkit-dockerfile --engine ferrocrate`
- Docker: the dockerd worker's hijacked BuildKit control connection stays open, sends the HTTP/2 SETTINGS preface, and permits `ListWorkers` and solves. Ferrocrate: clients receive `error reading server preface: connection reset by peer` or `raw-read unix @->/tmp/buildkit-integration…: use of closed network connection`; many subsequent sandbox wrappers end with `KeyboardInterrupt` when the timed-out worker is stopped.
- cause: S34's `/grpc` routing is present, but the upgraded control connection is still torn down before the embedded BuildKit gRPC server completes its HTTP/2 handshake. The existing S5 verification notes the matching `buildkit control: h2 handshake failed: Broken pipe` followed by a Tokio blocking-runtime drop panic; that observation was explicitly left without its own ticket. This is therefore a lifecycle/handoff defect after S34's route selection, not S34's former 404.
- scope: every BuildKit Dockerfile frontend and worker path that uses the Docker-compatible BuildKit control proxy. Of the 1,698 Ferrocrate-only failing records, 240 retain a direct reset/closed-connection diagnostic and 747 retain the resulting sandbox interruption; truncated stderr tails obscure the same upstream error in many remaining records.
- test: retain S34's raw upgraded-connection probe, but assert that after the client preface the server emits SETTINGS and remains usable for `ListWorkers`; run a solve that keeps the gRPC stream alive through result/status completion and assert no handshake error or Tokio panic in daemon stderr.

## Fix
The HTTP parser was consuming bytes past the upgrade response, so the h2 server's own preface arrived truncated. Parser timeouts are now cleared before the connection hands off to h2, and the upgraded control connection's ownership is preserved through the h2 handshake and the full solve lifecycle instead of being torn down early.
