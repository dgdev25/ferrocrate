# S176 — `compose convert` over helm charts / kubernetes manifests: `invalid type: null, expected a map`

- suite: compose-e2e · class: product defect · status: closed (ea7b72d6; retested 2026-08-29) · first seen: 2026-08-28
- command: `docker compose convert` (or the bridge path used by TestConvertAndTransformList) against a helm chart and a kubernetes manifest
- Docker (compose + bridge tooling): transforms the input and exits 0.
- Ferrocrate: exit 1, `Error response from daemon: invalid type: null, expected a map at line 1 column 1620` — the YAML/JSON document deserializer requires a mapping at the document root and the input (or an intermediate patch) is null there.
- impact: 2 failures (helm_charts, kubernetes_manifests); the whole convert/transform path is unusable for these inputs.
- regression tests: serde deserialization of a YAML document that contains explicit `null` values and of an empty document; an integration test running convert over the suite's helm fixture.

Fix: the null `EndpointsConfig` half was already fixed by S169 (`3104fc06`), which unmasked the next decoder on the same create body: Go's `HostConfig` has no `omitempty` on `NetworkMode`, so compose's unset mode arrived as `""` and the create parser rejected it with `network: name is required`. The parser now maps an absent or empty mode to the default network like Docker. Retest 2026-08-29 at `ea7b72d6`: `docker compose bridge convert` over `pkg/e2e/fixtures/bridge/compose.yaml` exits 0 for both `docker/compose-bridge-helm:v0.0.3` and `docker/compose-bridge-kubernetes:v0.0.3`, byte-identical to the Docker 29.7.2 oracle and to the upstream `expected-helm`/`expected-kubernetes` fixtures; upstream `TestConvertAndTransformList` passes 3/3 runs. Regression test: `container_create_treats_empty_network_mode_as_the_default_network` parses the captured Go-shaped convert create payload (1629-byte body, `NetworkMode:""`, `EndpointsConfig:null`) and asserts the default network.
