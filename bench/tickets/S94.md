# S94 — build: Node native addon is unavailable when the Dockerfile test step runs
- app: docker-todo · step: `build` · class: product · status: closed (71fac8b8) · first seen: 2026-08-27
- command: `cd /data/dev/bench-apps/docker-todo && ferro-cli build -t bench/docker-todo:latest .`.
- Docker: builds successfully. Ferrocrate reaches `npm run test`, where the sqlite persistence test fails while loading `node_modules/sqlite3/lib/sqlite3.js`; the other four Jest suites pass.
- cause: Ferrocrate batched every `COPY --from` before every `RUN`, losing Dockerfile instruction ordering. In docker-todo, it copied the compiled sqlite3 binding before `npm ci`; that command then removed `node_modules/sqlite3/build`, so the later test could not load the native addon. This is distinct from S15: named stages resolve and the RUN step executes, but the artifact transfer occurred at the wrong point in the layer transition.
- impact: the failed initial image build cascades into 32 image, lifecycle, network, Compose and error-path product failures.
- fix: preserve/install the platform-native addon artefact through the relevant RUN/layer transition, or make the build sandbox's Node ABI/platform match the image stage. Add a Dockerfile regression that installs `sqlite3` and requires it in a subsequent RUN test.

## Fix
Stage execution now records the first `COPY --from` that follows a `RUN`. It runs the preceding commands, copies the source-stage artifact into the stage root, then runs the remaining commands. The source-stage dependency graph, context consumption check, and checkpoint identity include these post-RUN copies, so the runtime artifact and cache/checkpoint behavior stay aligned. `COPY --from` also retains every source before its destination, allowing docker-todo's final stage to copy both package manifests before its production install.

## Verification
`checkpoint_restore_preserves_artifacts_copied_from_a_build_stage` now puts `COPY --from=addon-build` after a RUN that deletes the destination. It failed before the fix because all copies ran before the delete, and passes after it. The fixture models sqlite3's build-to-test transition and validates both the initial build and checkpoint restore. `copy_from_multiple_sources_preserves_each_source` verifies the final-stage package-manifest transfer.
