# S185 — compose: services without an explicit image/build are rejected where Docker accepts the project
- app: docker-flask · steps: compose-up, compose-health, compose-ps, compose-logs, compose-down · class: product · status: open · first seen: 2026-08-28
- command: `cd /data/dev/bench-apps/docker-flask && ferro-cli compose up -d` through `bench/ferro-adapter.sh`.
- Docker: accepts the project and starts the selected Compose services.
- Ferrocrate: `compose up` fails with `compose validation error: service 'css' must specify image or build`; subsequent Compose verbs similarly reject `worker` or `web` for the same requirement.
- cause: Compose validation requires every service model to carry an explicit `image` or `build` field, instead of applying Docker Compose’s project/profile/extension semantics for the service definitions in this application.
- scope: Compose projects containing services that Docker accepts through those semantics; validation blocks the entire project before service startup.
- test: parse and bring up a fixture with the same service shape as docker-flask, then assert `up`, `ps`, `logs`, and `down` complete under the same selected profiles as Docker.
- proof: fresh isolated 2026-08-28 full-app matrix at head `e7145b7d`, `bench/results/2026-08-28/docker-flask-ferrocrate.jsonl`. This is not S153: the former `entrypoint` sequence parse error is absent from the fresh record, and the new error is the explicit image/build validation failure.
