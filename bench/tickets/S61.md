# S61 — container ids are not Docker-shaped, and the two code paths disagree
- component: ferro-cli, docker-compat daemon · class: product · status: open · first seen: 2026-08-27
- Docker: a container id is 64 lowercase hexadecimal characters; clients accept the 12-character short form.
- Ferrocrate, native path: `13bc701a883d9d50e7ea2b0402857a02`, 32 hexadecimal characters.
- Ferrocrate, docker-compat path: `d18cfaa37bb577b6d-0`, 17 hexadecimal characters, a hyphen and an ordinal.
- consequences: a client that validates the id, or slices it to the 12-character short form, mishandles both. The hyphenated form is not a valid id by any Docker client's reckoning. The two paths disagreeing means an id learned through one is not necessarily usable in the other.
- fix: mint 64 hexadecimal characters in both paths, from the same generator.
- test: assert both paths produce 64 lowercase hexadecimal characters, and that the 12-character prefix addresses the container.
- found while fixing S28: `run -d` stdout is now the bare id, which exposed that the id itself is malformed.
