# S93 — run: environment assignment with a YAML-derived quoted value is split before CLI parsing
- app: node-getting-started · step: `run-detached` · class: product · status: open · first seen: 2026-08-27
- command: run the app bench manifest with `env: {PORT: "3000"}`.
- Docker: starts the app. Ferrocrate: `run: env must be KEY=VALUE`.
- cause: the benchmark-generated `-e` argument reaches Ferrocrate as a value split around the quoted YAML scalar, and the CLI then rejects the non-assignment fragment. Docker accepts the same runner invocation, so this is an observable CLI-compatibility gap rather than an app failure.
- impact: 25 product failures cascade from the missing initial container, including logs, inspect, lifecycle, commit/export, network run and Compose follow-ons.
- fix: preserve one `-e KEY=VALUE` argument through adapter/CLI parsing (including quoted values) and add a regression from the exact manifest scalar.
