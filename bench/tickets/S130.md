# S130 — Docker `/events` stream: object-form filters ignored, history replayed, lifecycle events carry no name or labels

- suite: compose-e2e · class: product defect (compat contract) · status: closed · first seen: 2026-08-27
- retest: 2026-08-28T07:47Z uncontended run at the S131 fix (`bench/results/2026-08-28/suite-compose-e2e-ferrocrate.jsonl`, 147 records: 43 pass / 96 fail / 8 skip). The full suite completed in ~45 minutes with no stall, zero hits for `invalid host port`, and no events-stream timeout failure. `up --abort-on-container-exit` and the watch tests now return.
- command: `docker events --filters '{"type":{"container":true}}' --filters 'label=com.docker.compose.project=demo'`; repro: `FILE=/tmp/large-repro/small.txt docker-compose -f pkg/e2e/fixtures/logs-test/cat.yaml --project-name <name> up --abort-on-container-exit --menu=false`
- required contract: `GET /v1.43/events` accepts Docker's three filter forms (`filters={"type":{"container":true}}` object form, `{"type":["container"]}` array form, `type=container` plain form); without `since` it streams only events that happen after the call connects; every container lifecycle event carries the container's `name` and full label set in `Actor.Attributes`.
- impact: total. docker/compose's `up --abort-on-container-exit` event monitor filters on `com.docker.compose.*` labels and returns when its watched set drains. The three defects together (stale creates enter the set, replayed creates from other projects enter the set, lifecycle events are invisible to the label gate) keep the set non-empty forever, so the monitor never returns, `globalCtx` never cancels, and compose hangs until go test's 120-minute timeout. Both HEAD runs stalled at 45 of ~270 tests; the pre-regression binary completed the same suite in 5–14 minutes.
- fix: `ferro-core/src/runtime.rs` `container_event_attributes()` stamps runtime-emitted container events (`die`, `oom`, `start`, `stop`, `kill`, `restart`, `health_status`) with `name` and the record's labels; `ferro-cli/src/main.rs` `DockerEventStore::query` reuses `parse_docker_event_filters` (which already parsed the object form) instead of a local closure that dropped it; `stream_docker_events` seeds the cursor at `max_event_id()` when no `since` is given. Regression tests: `container_event_attributes_carry_name_and_labels`, `docker_event_query_applies_object_form_filters`, `docker_event_store_max_event_id_tracks_journal_tail`.
- follow-up (2026-08-28): two more stream defects found during the retest. `until` was parsed by the caller path but ignored by `stream_docker_events` — no replay, and the response never terminated, which blocks `docker events --until` and any client that reads to EOF. And the no-`since` cursor seeded at `max_event_id()`, which returned 0 for an empty journal while event ids start at 0, so a subscriber on a fresh daemon missed the first event and compose hung exactly as before. Fixes: `stream_docker_events` parses `until`, replays from the journal start, and writes the terminating `0\r\n\r\n` chunk at the bound; `max_event_id()` returns `Option<u64>` (`None` = nothing to skip). Regression tests: `docker_events_until_replays_history_and_closes_the_stream`, `docker_events_follow_stream_uses_chunked_jsonl_framing` (now subscribes before the event), `docker_event_store_max_event_id_tracks_journal_tail` (uses a journaling second append).

## Evidence

- `/tmp/proxy-conn-16.txt` records the actual `/events` response body compose received: `die` events with `Attributes: {exitCode, httpStatus, image, scope, status}` — no `name`, no labels — and a request with `filters={"label":{...},"type":{"container":true}}` (object form) and no `since`.
- A MITM proxy on the socket proved the attach stream EOFs normally and compose proceeds to list containers and issue stop before hanging, which rules out the attach path.
- A fresh (empty) daemon store still hung, which rules out history replay as the sole cause; the filter and label defects reproduce it on an empty store.
