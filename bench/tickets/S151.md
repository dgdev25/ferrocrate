# S151 — daemon: `POST /containers/create` accepts or misclassifies invalid Docker request bodies
- suite: moby-integration (7 product failures in `TestCreateValidation`) · class: product · status: open · first seen: 2026-08-27
- command: `POST /v1.45/containers/create` with an empty body/config, malformed exposed-port key, too-small `HostConfig.Memory`, or invalid `HostConfig.RestartPolicy`.
- Docker: returns `400 Bad Request` with Docker-compatible validation errors: empty JSON/body is invalid; `19039;1230` is an invalid port; memory below 6 MiB is rejected; restart policy names and retry-count constraints are validated.
- Ferrocrate: returned 500 for empty-body, unknown restart-policy, and negative-retry cases; returned 201 for malformed port syntax and retry-count on `always`; exposed `CpuShares unsupported` before validating the too-small memory limit; and returned a serde missing-field message instead of the Docker empty-config diagnostic.
- cause: the Docker-compat create handler deserializes or translates requests before applying Docker's request-validation order and lacks several semantic validators. These are one input-validation boundary, not independent test-name failures.
- scope: add a pre-runtime Docker create validator that reports 400 and Docker-compatible messages for body/config presence, port syntax, minimum memory, and restart-policy constraints before unsupported-feature translation.
- test: mirror Moby `integration/container/TestCreateValidation` in the socket compatibility tests, asserting status and message for all seven invalid payloads plus the valid `on-failure` zero-retry case.
