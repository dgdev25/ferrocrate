# S27 — compose: every service is refused as an unauthorized child
- apps: all eleven with a compose file · step: compose-up · class: product · status: closed — the digest rejection is fixed and all launch paths share one resolver; final qualification remains blocked by classic conformance failures, unrelated runtime contamination, and remaining Compose compatibility failures · first seen: 2026-08-26, present in every run since
- command: `ferro-cli compose up -d --build`
- Docker: brings the stack up. Ferrocrate: `compose partial result: <service> run failed: runtime mutation mediation failed: compose execution request digest does not match authorized child`.
- cause: `ferro-core/src/runtime.rs` computes `run_execution_digest` from the pinned image, command, environment, labels, annotations, healthcheck, restart policy, limits, workdir, user, name, port mappings and the normalized request, then rejects the launch unless it equals the digest compose authorized through `fanout_request_digest_matches`. Compose authorized unresolved image defaults (`workdir: None`, `user: None`, and an incomplete command), while `handle_run` resolved the image command and the runtime later inherited `WorkingDir` and `User`. The check arrived with `d806d82b`.
- fix: Compose resolves the pinned image configuration once after image prerequisites and before child authorization. It binds command, environment, workdir, user, healthcheck, and image-declared volume targets into `normalized_run_execution_digest`, then passes the same `ResolvedRunImageExecution` object and pre-materialized anonymous-volume mounts to `handle_run`. `handle_run`, direct `run`, and Docker create/start use the same override application with caller values taking precedence over image defaults; the launcher consumes the supplied resolved object rather than rebuilding its own view. The comparison remains enforced; a changed command is still rejected.
- to find it: log both digests and their inputs at the point of comparison, then diff the input sets. The likely culprits are fields the runtime fills in after compose authorized the child: values inherited from the image config, a normalized network mode, or a generated container name.
- scale, measured 2026-08-27 with docker/compose's own e2e suite: 270 tests, Docker passes 264, Ferrocrate passes 22. That is 229 product failures against 6 that fail on both engines. The entire fourteen-application bench has 144. This single defect is the largest in the project.
