# S32 — daemon: image reference arriving URL-encoded is rejected as invalid
- suite: compose-e2e (12+ failures behind it, all build-related) · class: product · status: open · first seen: 2026-08-27
- command: `docker compose build` with the buildx bake path (bench compose-e2e, e.g. TestCheckWarningXInitialSyn pulls `moby/buildkit:buildx-stable-1`)
- Docker: accepts the pull; buildx sends image references percent-encoded in the API path (e.g. `docker.io%2Fmoby%2Fbuildkit:buildx-stable-1`) and Docker decodes them server-side.
- Ferrocrate: `Error response from daemon: invalid image reference: docker.io%2Fmoby%2Fbuildkit:buildx-stable-1` — the raw encoded string reaches reference validation, so every buildx-driven image pull fails. Same shape seen for `docker.io%2Flibrary%2Falpine:latest`.
- cause: the HTTP layer does not percent-decode the image reference segment of the request path before validation. `/` and `:` arrive as `%2F` and `%3A`.
- scope: request path decoding in the Docker-compat API server, image-load path (POST /images/load, pull, create). Must decode before parsing the reference, not after.
- test: `curl --unix-socket <sock> -X POST "http://localhost/v1.43/images/create?fromImage=docker.io%2Flibrary%2Falpine:latest&tag=latest"` must succeed.
