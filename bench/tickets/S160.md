# S160 — BuildKit Dockerfile lint rules are delivered but do not match Dockerfile-check semantics
- suite: buildkit-dockerfile (176 failing warning assertions after the S142 delivery fix) · class: product · status: open · first seen: 2026-08-28
- command: `GO_TEST_TIMEOUT=0 SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh buildkit-dockerfile --engine ferrocrate`.
- Docker: Dockerfile checks emit exactly the rule diagnostics selected by the Dockerfile and `--check` options. Ferrocrate now reaches both progress and unmarshalled warning paths, but emits zero warnings where one or more are required, emits warnings when zero are requested, or produces a different message (for example no undefined-variable suggestion). The result is `expected N, actual M` in `dockerfile_check_test.go`, not the S142 missing-result signature.
- cause: the local Dockerfile parser/validator does not implement BuildKit's lint-rule evaluation and option filtering with Docker-compatible semantics. S142's formerly missing transport has exposed this separate semantic gap.
- scope: rule selection plus warning content/count for casing, ignored-copy, undefined-argument/variable, JSON-args, stage-name, EXPOSE, legacy-format, and related Dockerfile checks.
- test: execute one enabled and one disabled stable rule through both progress and unmarshal forms; assert identical rule name, detail, location, URL, and count to the Docker oracle.
- evidence: fresh failures across `TestRuleCheckOption` (48), `TestCopyIgnoredFiles` (20), `TestUnmatchedVars` (14), `TestUndeclaredArg` (13), and the other `checkLinterWarnings` variants.

2026-08-29 partial fix: `JSONArgsRecommended` and `skip=` selection from Dockerfile directives and `BUILDKIT_DOCKERFILE_CHECK` are now evaluated. This ticket remains open: the remaining listed rule families still need Docker-compatible evaluation and diagnostics.
