# S38 — daemon: the whole /volumes API surface returns bare 404
- suite: compose-e2e (50+ failures behind it) · class: product · status: duplicate · first seen: 2026-08-27
- command: `curl --unix-socket <sock> ... http://localhost/v1.43/volumes` against the Docker-compat socket
- Docker: `GET /volumes` lists volumes; `POST /volumes/create`, `GET /volumes/{name}`, `DELETE /volumes/{name}` all work.
- Ferrocrate: every one returns `404 {"message":"not found"}` — no route exists. Verified with curl on 2026-08-27 against release-artifacts/ferro-cli.
- cause: `docker compose down -v` and `compose config`-validation list volumes by project label; the 404 aborts them, so a large fraction of compose-e2e tests fail in setup or teardown before the behaviour under test runs. The bare "not found" also loses the object type, so clients cannot tell a missing volume from a missing endpoint.
- scope: volumes list/create/inspect/delete in the Docker-compat HTTP server, plus label filters on the list call. The CLI already has volume commands (bench matrix exercises them), so this is the API route, not the store.
- test: start the daemon, `POST /v1.43/volumes/create` `{"Name":"probe"}`, assert 201; `GET /v1.43/volumes` contains it; `DELETE /v1.43/volumes/probe` returns 204; second GET returns 404 with "no such volume".
- resolution: duplicate of resolved S29. `589f816e` supplies the volume socket contract (create/delete/inspect and Docker-shaped missing-volume errors).
