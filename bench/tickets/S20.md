# S20 — image save/load and export flag handling
- source: real-app bench · steps: export, load · class: product · status: closed · first seen: 2026-08-26
- `export` requires `--output` where Docker also accepts `-o` and a redirect to stdout; the bench adapter's `-o` mapping does not reach the CLI (8 failures).
- `load -i <file>` fails with `docker: load read failed: No such file or directory (os error 2)` even when the file exists and was written by `save` (5 failures).
- fix: accept `-o`/`--output` and stdout for `export`; make `load -i` resolve and read the archive path; round-trip test: `save -o f && rmi && load -i f && run` the restored image.

## Verification
Verified 2026-08-27 against the fourteen-application bench. `load` passes on 7 of 9 applications and `export` on every application whose container starts.
