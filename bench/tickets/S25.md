- command: `ferro-cli build -t bench/spring-petclinic:latest .` on the app's own Dockerfile
- Docker: build passes. Ferrocrate: Maven fails with `checkstyle violations`, so the build exits non-zero and 32 later steps fail behind it.
- likely cause: the build context differs from Docker's. Candidates, in order: `.dockerignore` entries not applied the same way, so checkstyle scans files Docker excludes; `COPY . .` placing context contents differently after the run-4 change; file modes or line endings altered in transit.
- reproduce: build the app with both engines, then `docker run --rm <image> find /workspace -newer pom.xml` on each and compare the file lists. The first difference is the cause.
- note: the recorded stderr keeps only the last 400 bytes, which held Maven's epilogue rather than the violation names. Diagnosing this needs the build journal to retain the failing step's full output.
