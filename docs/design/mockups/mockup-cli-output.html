2. FERROCRATE RUN COMMAND OUTPUT

The ferrocrate run command creates and starts a container. Output includes image pull progress, container creation status, and runtime information.

Design Notes - ferrocrate run

  • Progress bars: Show layer-by-layer pull progress with transfer rates
  • ASCII boxes: Group related information with clear visual boundaries
  • Timing information: Display elapsed time for performance transparency
  • Container ID: Output short ID (12 chars) on last line for scripting capture
  • Rootless indicator: Always show security context for awareness

3. FERROCRATE PS TABLE OUTPUT

The ferrocrate ps command lists running containers in a formatted table. Supports multiple output formats including table, JSON, and custom Go templates.

ferrocrate ps
$ ferrocrate ps

Design Notes - ferrocrate ps

  • Color-coded status: Green for running, yellow for paused, red for exited/unhealthy
  • Inline resource bars: Visual CPU usage in wide format
  • Truncation: Long commands truncated with ellipsis, full on hover/inspect
  • Summary footer: Total count with status breakdown
  • Accessibility: Status indicated by both color and text symbol

4. FERROCRATE LOGS STREAMING OUTPUT

The ferrocrate logs command streams container logs with configurable log level filtering, timestamps, and color coding for different sources.

ferrocrate logs -f --tail 20 web-server
$ ferrocrate logs -f --tail 20 web-server
14:32:01.241 INFO [nginx] Starting nginx server on port 80...
14:32:01.258 INFO [nginx] Configuration loaded from /etc/nginx/nginx.conf
14:32:01.312 DEBUG [ferrocrate] Health check registered: interval=30s, timeout=5s
14:32:01.445 INFO [nginx] Listening on 0.0.0.0:80
14:32:15.892 DEBUG [access] GET / HTTP/1.1 200 615 "-" "curl/7.88.1" 0.001s
14:32:45.123 WARN [nginx] upstream server temporarily disabled while connecting to upstream
14:33:01.456 ERROR [nginx] connect() failed (111: Connection refused) while connecting to upstream
14:33:01.512 INFO [ferrocrate] AI Analysis: Connection refused to upstream. Recommend checking backend container status.
14:33:02.001 TRACE [ferrocrate] Resource prediction: memory_trend=stable, cpu_trend=low_usage
14:33:15 INFO [access] GET /health HTTP/1.1 200 15 "-" "health-check/1.0" 0.000s

Log Level Color Scheme

log-level-reference
LEVEL COLOR USAGE EXAMPLE
TRACE Muted Gray Very detailed diagnostic info Variable dumps, internal state
DEBUG Gray Detailed diagnostic info Function entry/exit, decisions
INFO Blue General operational messages Server started, request logged
WARN Yellow Warning conditions Deprecated API, retry attempt
ERROR Red Error conditions Connection failed, parse error

Design Notes - ferrocrate logs

  • Structured format: Timestamp + Level + Source + Message for consistent parsing
  • Color coding: Instant visual identification of log severity
  • AI annotations: FerroCrate can inject AI analysis into log stream
  • Follow mode: Cursor animation indicates live streaming
  • Filtering: --level flag to filter by severity (warn,error only)
  • Accessibility: Log level badges provide non-color indication

5. ERROR OUTPUT DESIGN

Error messages follow a consistent structure with actionable guidance and suggested remediation steps.

ferrocrate run nonexistent-image:latest
$ ferrocrate run nonexistent-image:latest
ERROR
Failed to pull image: nonexistent-image:latest
Code: IMAGE_NOT_FOUND
Source: docker.io/library/nonexistent-image:latest
Reason: The requested image does not exist in the registry
Suggestions:
1. Check the image name for typos
2. Verify the image exists: ferrocrate search nonexistent-image
3. Try a different tag: ferrocrate run nonexistent-image:stable
For more help, run: ferrocrate help run

Design Notes - Error Output

  • Structured errors: Error code, source, reason for debugging
  • Actionable suggestions: Numbered list of remediation steps
  • Help reference: Link to relevant documentation
  • Visual distinction: Red border on error box for immediate recognition
  • Exit codes: Consistent exit codes for scripting (documented separately)

6. AI DECISION OUTPUT

When AI features make decisions, output includes explainability information accessible via ferrocrate explain command.

ferrocrate explain ai-decision-2026-0211-001
$ ferrocrate explain ai-decision-2026-0211-001
AI DECISION EXPLANATION
Decision ID: ai-decision-2026-0211-001
Timestamp: 2026-02-11 14:33:01 UTC
Action: MEMORY_LIMIT_ADJUSTMENT
Target: container:db-primary (fc9e4f2a1b8c)
Confidence: 87%
REASONING:
Observed memory usage pattern over 72-hour window showed consistent peak usage of 1.2GB during batch processing (02:00-04:00 UTC). Current limit of 512MB caused 3 OOM events. Recommendation to increase to 2GB with burst allowance of 4GB.
INPUT DATA:
memory_samples: 2,847 data points over 72h
oom_events: 3 (all during batch window)
avg_usage: 312 MB | peak_usage: 1.24 GB
ACTION TAKEN:
Memory limit increased from 512 MB to 2 GB
Burst limit set to 4 GB
To undo this decision: ferrocrate undo ai-decision-2026-0211-001
To disable AI adjustments: ferrocrate config set ai.auto_adjust=false

Design Notes - AI Explainability

  • Full transparency: Every AI decision has unique ID and full explanation
  • Confidence score: Shows AI certainty level for the decision
  • Input data summary: Shows what data informed the decision
  • Undo capability: Every decision can be reverted
  • Opt-out path: Clear instructions to disable AI features
