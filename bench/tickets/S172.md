# S172 — `up` after a BuildKit build: `network error: rootless host and container ports must be non-zero`

- suite: compose-e2e · class: product defect · status: closed (681a250e resolves the ephemeral sentinel at start; verified `run -d -p :8080` serves through the assigned port and BuildKit `up --build` with `ports: "8081"` starts and publishes) · first seen: 2026-08-28
- command: `DOCKER_BUILDKIT=1 docker compose up --build` (TestLocalComposeBuild/DOCKER_BUILDKIT=1 build_as_part_of_up, no_rebuild_when_up_again, rebuild_when_up_--build)
- Docker: builds then starts the service; the container runs.
- Ferrocrate: the build succeeds, the container reaches `Started`, then `network error: rootless host and container ports must be non-zero` and `up` exits 1. The check runs against a spec whose host or container port is still the 0/ephemeral sentinel at forwarding time, so start-time ephemeral port assignment is missing — the same gap S131 records for the listing side.
- impact: 3 failures; blocks the BuildKit build-then-up path.
- regression tests: `run -d -p 80` style create with an empty `HostPort`, assert start succeeds and inspect shows an assigned `PublicPort`; compose `up --build` over the build-test fixture with BUILDKIT=1.
- fix: `resolve_ephemeral_host_ports` (ferro-core/src/runtime.rs) replaces every `host_port == 0` sentinel with a kernel-assigned free port on both the create-and-start path and the start/restart path, before the network backend validates the mappings and installs forwarding; the assigned port is persisted with the record, so inspect shows the `HostPort`/`PublicPort` Docker reports. Unit tests `ephemeral_sentinel_host_port_is_resolved_at_start` and `ephemeral_sentinel_with_a_zero_container_port_is_rejected`; ignored rootless integration test `ephemeral_published_host_port_is_assigned_at_start` (run/start/inspect with `-p :80`).
