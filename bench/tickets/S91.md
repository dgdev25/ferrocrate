# S91 — compose: string-form `healthcheck.test` is rejected
- app: docker-flask · steps: `compose-up`, `compose-ps`, `compose-logs`, `compose-down` · class: product · status: open · first seen: 2026-08-27
- command: `cd /data/dev/bench-apps/docker-flask && ferro-cli compose up -d`.
- Docker: accepts `healthcheck.test: curl localhost:8000/up`. Ferrocrate: `compose parse error: services.web.healthcheck.test: invalid type: string ..., expected a sequence`.
- cause: the Compose model deserializes `healthcheck.test` only as a sequence. Compose permits its shell-command scalar form as well as the list form.
- impact: five product failures in the fresh rerun; the health and management steps are consequences of the rejected Compose document.
- fix: deserialize `test` as string-or-sequence, normalize a scalar to Docker's shell-form healthcheck representation, and preserve the existing `CMD`/`CMD-SHELL` validation. Add scalar and sequence regression fixtures.
