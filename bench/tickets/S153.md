# S153 — compose: sequence-form `entrypoint` is rejected
- app: docker-flask · steps: `compose-up`, `compose-health`, `compose-ps`, `compose-logs`, `compose-down` · class: product · status: open · first seen: 2026-08-28
- command: `cd /data/dev/bench-apps/docker-flask && ferro-cli compose up -d`.
- Docker: accepts the worker service's list-form `entrypoint` and starts the Compose project.
- Ferrocrate: exits 1 with `compose parse error: services.worker.entrypoint: invalid type: sequence, expected a string at line 94 column 17`.
- cause: the Compose model accepts only a scalar command for `entrypoint`, while Compose permits both a shell-form string and an exec-form sequence.
- scope: every Compose service using the documented list form; S91 fixed scalar `healthcheck.test`, but not this distinct string-or-sequence field.
- test: parse and run a fixture with `entrypoint: ["/bin/sh", "-c", "echo ok"]`; retain scalar entrypoint coverage and assert both normalize to Docker-compatible execution.
