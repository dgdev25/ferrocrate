# S177 — `compose up` with an image ID treats the 64-hex ID as a repository name

- suite: compose-e2e · class: product defect · status: closed · first seen: 2026-08-28 · fixed: 2026-08-28
- command: `docker compose up` with `image: <64-byte hex image ID>` (TestUpImageID)
- Docker: resolves the ID locally and runs the container, no pull.
- Ferrocrate: attempts a pull and fails with `invalid repository name (<hex>), cannot specify 64-byte hexadecimal strings`.
- impact: 1 failure.
- regression tests: `docker run <image-id>` and compose `up` with an ID both asserting no pull is attempted and the container starts.
- root cause: local IDs were parsed as registry names before store lookup; the rejected first fix also authorized one digest while deleting an unsnapshotted, mutable set of references.
- fix: a shared case-insensitive selector resolves exact IDs and unique prefixes locally, while forced ID removal uses an immutable digest/reference plan, one authorization per reference, and an atomic inventory comparison before deletion.
- proof: focused core tests cover selector, runtime/signature, repository-digest fetch identity, per-reference authorization, and concurrent inventory drift. Operational CLI/API tests cover uppercase direct run, Compose, daemon create/start, inspect/history/tag/remove, missing and ambiguous selectors, one-tag ID removal, multi-tag force conflicts/deletion, and local/remote/HTTP force propagation.
