# S37 — ferro-cri: CRI v1 image API answers with invalid gRPC wire-format data, so critest cannot connect
- suite: critest (all 137 failures behind it; 0 real specs pass) · class: product · status: open · first seen: 2026-08-27

- Docker/CRI contract: the runtime endpoint answers the CRI v1 `ImageService` (`runtime.v1.ImageService/ListImages` etc.) with valid protobuf over gRPC; every conformant CRI client can validate the connection.
- Ferrocrate: critest's connection validation (`validate service connection: validate CRI v1 image API`) fails on every spec with `rpc error: code = Internal desc = grpc: failed to unmarshal the received message: proto: cannot parse invalid wire-format data`. - cause: the ferro-cri gRPC image service emits a response the Go gRPC client cannot parse as protobuf: either the message is serialized wrong, or the HTTP/2 framing/message-length prefix on the stream is malformed. - scope: the CRI v1 image service handlers in ferro-cri and/or the gRPC codec path (message framing, length prefix, compression flag). Until this is fixed no critest spec can run, so the whole CRI conformance surface is unverified.
- test: start ferro-cri, then `critest --runtime-endpoint <sock> --ginkgo.focus 'image list'` must connect and report the spec result rather than failing connection validation; a plain gRPC `ListImages` call against the socket must return a parseable `ListImagesResponse`.
