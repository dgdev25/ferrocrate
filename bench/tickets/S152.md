# S152 — daemon: Docker `HostConfig.IpcMode=host` is rejected rather than sharing host IPC
- suite: moby-integration (1 product failure: `TestAPIIpcModeHost`) · class: product · status: closed (explicit feature boundary) · first seen: 2026-08-27
- command: create and start a BusyBox container through the Docker API with `HostConfig.IpcMode: "host"`, then exchange a file through `/dev/shm`.
- Docker: accepts the create request and shares the host IPC namespace; a file made in the container is visible in host `/dev/shm`.
- Ferrocrate: returns `501 Not Implemented` for `HostConfig.IpcMode=host` with an explicit namespace-runtime feature boundary; it does not claim host IPC sharing without the required `/dev/shm` mount and lifecycle support.
- cause: the compatibility request translator recognizes `IpcMode` only as an unsupported HostConfig field and the runtime has no host-IPC namespace execution path.
- scope: this requires explicit namespace/runtime support and host-safety policy, not merely accepting the JSON field. Do not silently accept it without providing the Docker isolation semantics.
- test: run Moby's `TestAPIIpcModeHost` equivalent only when host IPC is supported; otherwise retain an explicit feature-boundary response.
