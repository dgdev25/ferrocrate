# S71 — Dockerfile RUN shell form beginning with `[` is parsed as JSON exec form
- suite: buildkit-dockerfile (12 failures behind it) · class: product · status: closed · first seen: 2026-08-27
- command: `SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh buildkit-dockerfile --engine ferrocrate`
- Docker: security-insecure Dockerfile RUN steps execute (or are rejected specifically for a missing entitlement). Ferrocrate: `invalid Dockerfile: invalid JSON array: expected ',' or ']'`.
- cause: `parse_exec_or_shell` in `ferro-core/src/dockerfile_build.rs` treats every trimmed RUN instruction that starts with `[` as JSON and passes it to `parse_json_array`. The BuildKit security tests use a shell command beginning with the POSIX `[` utility, so it is not JSON exec syntax and should remain shell form.
- scope: 12 distinct non-interruption failures across the `frontend=builtin` security-insecure and insecure-device variants; their entitlement assertions are masked by this earlier parser error.
- test: add the existing Dockerfile parser-pattern coverage for `RUN [ \"$(command)\" == \"value\" ]`, asserting shell parsing, while retaining valid JSON-array RUN coverage.

## Fix
Not attempted: this is measurement and triage, not remediation.


## Verification
Fixed 2026-08-27. `parse_exec_or_shell` now attempts a JSON array parse first and falls back to shell form on any failure, rather than assuming every '[' prefix is JSON. Verified: `run_bracket_utility_executes_as_shell_form`, `run_bracket_utility_falls_back_to_shell_form`, and `run_json_array_still_parses_as_exec_form` all pass; full ferro-core lib suite 695/695.
