# S47 — run: `wait` reports status_code 0 after a kill, and prints a key=value line
- apps: all · step: wait · class: product · status: open · first seen: 2026-08-27
- command: `wait <name>` on a container that was killed (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `kill fz-<tag>`, `wait fz-<tag>`)
- Docker: exit 0, prints `137` — the container's exit status, 128+signal.
- Ferrocrate: exit 0, prints `wait: container=<id> status_code=0`. Two divergences: the exit status is wrong (0, not 137 — the kill signal is lost), and the output is a key=value line with the container id instead of the bare number.
- cause: the wait path reads a stored exit code that was never set by the kill path (S41's status model), and formats the output in the CLI's house style instead of docker's bare integer.
- scope: every orchestration script that waits for a container and branches on its exit status — `wait` after a kill is exactly the "did it die on its own or was it killed" check, and it currently always says "clean exit".
- test: run detached, kill, wait; assert exit 0 and stdout `137`. Run detached, `kill --signal TERM`, wait; assert stdout `143`. Run a container with `true`, wait; assert stdout `0`.
