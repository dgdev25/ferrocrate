# S183 — `network disconnect` rejects a stopped container

- suite: compose-e2e · class: product defect (compat contract) · status: closed · first seen: 2026-08-28 · fixed: 2026-08-28
- command: compose's recreate path: `up -d` twice over a changed network spec; the engine detaches the old container (TestNetworkRecreate)
- Docker: disconnect accepts a created or stopped container; it applies no running-state check. Compose relies on this when it re-creates a container: it stops the container, then disconnects it from the network.
- Ferrocrate: `Error response from daemon: invalid container state: network disconnect requires a running or paused container`, so the whole `up -d` fails.
- impact: 1 failure directly; blocks every compose network-change recreate.
- regression tests: run a container, stop it, `network disconnect` it, assert exit 0 and that inspect no longer lists the container.

## Resolution

- Runtime detach separates live and terminal records. Running/paused detach retains verified route/veth teardown before persistence and reports post-effect persistence uncertainty. Stopped/exited and legacy killed detach validates and projects the endpoint, CAS-publishes it first, then attempts only idempotent helper/veth cleanup; a failed publication leaves the recorded attachment and does not start terminal cleanup. Present terminal resources are deleted only when durable owner, network, namespace, and ifindex identity agree.
- Docker-created pending containers persist explicit logical attachments. Pending publication distinguishes failures before rename (the old file remains authoritative and memory is restored) from uncertainty after rename (the detached visible snapshot remains in memory and the authorization outcome is unknown). It never rewrites old bytes over an ambiguous rename. Legacy pending files project their original network mode until first mutation.
- Regressions cover stopped/exited/legacy killed, live ownership enforcement and verified veth teardown where capabilities permit, terminal CAS failure ordering, pre-rename and post-rename pending publication phases, and a capability-gated real rootless run → stop → native disconnect → inspect workload path. Environments without the required rootless namespace/helper capability report an explicit skip.
