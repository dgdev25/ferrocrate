# S26 — build: a stage layer holds the whole filesystem, not the change set
- apps: actix-basics, gin-basic (build refused); every image Ferrocrate builds is affected · step: build · class: product · status: fixed (bench revalidation blocked by Docker Hub 429) · first seen: 2026-08-27
- evidence in code: `build_stage` calls `build_layer_from_dir(&stage_root, None, compression)` (`ferro-core/src/dockerfile_build.rs`), which tars the entire stage root. The manifest then lists the base image's own descriptors *and* this layer, so the base content is stored twice.
- Docker records only what the stage changed, with whiteout entries for deletions.
- measured: actix-basics 4.44 GB and gin-basic 4.45 GB for the top layer. Two unrelated language stacks landing within 2 MB of each other is the signature: the size is the base image plus build output, not the application.
- why it appeared now: before the S15-S22 merge these builds failed early, at `cargo: not found` and the Go equivalent, so the rootfs held no compiler output and the layer measured 1.2 to 1.5 GB. The merge made the compilers run. The whole-rootfs behaviour is older than the merge; the merge only exposed it.
- consequence: images are several times larger than Docker's, pulls and pushes carry duplicate content, and the builds exceed any sane in-memory cap. S23's raised cap does not help these two.
- fix: diff the stage root against its parent and emit only added, changed and deleted paths, with `.wh.` whiteout entries for deletions. Stream the tar to a temporary file rather than a `Vec<u8>` while doing it, which also closes S23.
- test: build `FROM alpine:3.20` plus `RUN touch /marker`, then assert the top layer contains `/marker` and not `/bin/sh`. Compare the image size against Docker's for the same Dockerfile.
- fix (2026-08-27): snapshot the root before context/RUN application and stream the post-RUN filesystem diff to a temporary compressed tar. The diff contains only changed/added entries and OCI `.wh.<name>` whiteouts; its digest is then installed from the file. The context layer remains the existing context change set.
- proof: `run_layer_contains_only_changed_paths_and_whiteouts`, `run_layer_whiteouts_a_removed_directory_once_and_removes_it_when_applied`, and the multi-stage regression passed; `cargo test --workspace`, warning verification, and both 85/85 conformance modes completed. The isolated five-app bench ran to completion, but the fresh store hit Docker Hub's unauthenticated HTTP 429 while pulling Gin, Node, Todo, and Spring bases, so a fresh Docker-vs-Ferrocrate size comparison is pending registry access.
