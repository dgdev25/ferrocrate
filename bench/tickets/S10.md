# S10 — rootless networking: slirp4netns processes leak and hold host ports
- app: battleships · step: run-detached · class: product · status: open · first seen: 2026-08-26
- observed: 28 `slirp4netns` processes alive with 0 containers; `ferro-cli run -d -p 3210:3000 …` fails with `slirp4netns failed to add host forwarding: add_hostfwd failed`; `ss -ltnp` shows port 3210 owned by a leaked slirp4netns from a removed container.
- Docker: stop/rm releases the port.
- fix: terminate the container's slirp4netns on stop/kill/rm and on daemon start (reap orphans by api-socket path); a port-in-use error must name the holder.

## Impact seen in tooling, 2026-08-26
Leaked `slirp4netns` processes inherited the coordinator's `flock` file descriptor and held the host build lock, stalling a verification for ~50 minutes. Fixed on our side by closing fd 9 for children in `with-host-lock.sh`, but the leak itself is the defect: helpers must not outlive their container, and must not inherit unrelated descriptors.
