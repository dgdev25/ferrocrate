# S167 — run: `diff` on a fresh running container reports extra runtime dirs as changed

- apps: all · step: diff · class: product · status: open · first seen: 2026-08-28
- command: `run -d --name fz-<tag> alpine:3.20 sleep 300`, then `diff fz-<tag>` immediately, before any process inside touches the filesystem beyond normal startup
- Docker: exit 0, no output — a freshly started container that has done nothing beyond the runtime's own startup work shows no filesystem changes.
- Ferrocrate: exit 0, but reports `D /dev`, `D /proc`, `D /run`, `D /sys` as deleted. These are the standard kernel-provided mount points every container has; they should be excluded from the diff the same way S48 already excludes `/etc/resolv.conf`, `/etc/hostname`, `/etc/hosts`.
- cause: the diff implementation's runtime-injected-path exclusion list (added by S48) covers the resolver/hostname files but not the standard mount-point directories the runtime itself provisions.
- scope: every `diff` call on any container; the same runtime dirs would incorrectly show up as "changed" for any real usage.
- test: start a fresh container, run `diff` immediately, assert no output and exit 0; separately assert that a real file change inside `/dev` (if ever legitimately writable) is still detected.
- evidence: found by the 200-sequence differential fuzzer during the S40-S53 acceptance run, 2026-08-28, verified against Docker directly. 36 of 85 fuzzer divergences in this run were this exact class.
