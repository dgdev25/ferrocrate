# S162 — Dockerfile RUN mount/resource options are not applied by the BuildKit execution bridge
- suite: buildkit-dockerfile (at least 18 direct product failures) · class: product · status: open · first seen: 2026-08-28
- command: `GO_TEST_TIMEOUT=0 SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh buildkit-dockerfile --engine ferrocrate`.
- Docker: BuildKit applies supported `RUN --mount` ownership/tmpfs/cache settings and sandbox resource settings, and rejects misspelled mount flags at parse time. Ferrocrate reports cache-owner EPERM, rejects valid tmpfs-size syntax, sends `--security=sandbox`/unknown `--mont` through to the shell, cannot provide `/dev/shm`/cgroup expectations, or fails to create cache/mount output paths.
- cause: Dockerfile RUN options are only partially parsed and are not translated into the rootless BuildKit execution environment; validation and execution therefore diverge together from Docker's mount/resource contract.
- scope: cache mount uid/gid, tmpfs size, duplicate/meta mounts, shared memory size, cgroup parent/resources, ulimit, and invalid RUN mount flag diagnostics.
- test: run focused Dockerfiles for a valid cache uid/gid mount, valid tmpfs size, invalid `--mont`, and `/dev/shm` size; assert the expected mount state or early Docker-compatible validation error.
- evidence: fresh `TestCacheMountUser`, `TestMountTmpfsSize`, `TestMountDuplicate`, `TestMountMetaArg`, `TestMountInvalid`, `TestShmSize`, `TestCgroupParent`, `TestLinuxResources`, and `TestUlimit` failures.

Status note: partial — verified against Docker 29.7.2 and BuildKit's Dockerfile
frontend/LLB resource contract. The bridge now carries `shm-size`, `ulimit`,
`cgroup-parent`, memory/memswap, CPU quota/period/shares/cpuset, pids-limit,
selective/all-stage `no-cache`, and global/per-RUN network modes into execution.
On a privileged Linux worker these become a per-RUN cgroup-v2 leaf, cgroup
namespace/mount, rlimits, sized `/dev/shm`, and the requested host or isolated
network namespace; host mode requires the `network.host` entitlement. Cache,
tmpfs, bind, secret-file/secret-env, optional/required SSH, mount metadata, and
BuildKit key/type diagnostics are parsed before execution. Focused Rust
regressions cover each option family, cache filtering, byte-size syntax,
secret/SSH metadata, network selection, and invalid-option suggestions.

Remaining boundary: BuildKit session secret and SSH providers are not imported
by this gateway (only the existing CLI secret files and host SSH socket reach
the classic executor), and SSH uid/gid/mode needs a socket proxy. Rootless
nonzero cache/secret ownership needs subordinate-ID mapping, rootless tmpfs
cannot enforce its size with bubblewrap, and rootless cgroup resources require
a delegated cgroup root. Sandbox networking still lacks BuildKit's managed
outbound network (rootless sandbox shares the host network; privileged sandbox
is an isolated namespace), while `none` and entitled `host` are enforced.
Cache `from`/`source` and readonly cache mounts remain unsupported. Direct
client LLB definitions are not executed vertex-by-vertex, so their mount and
resource metadata remains outside this Dockerfile bridge change.
