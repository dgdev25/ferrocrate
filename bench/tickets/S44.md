# S44 — volume: `volume rm` of a missing volume exits 0 instead of 1
- apps: all · step: volume-rm · class: product · status: open · first seen: 2026-08-27
- command: `volume rm fzv-<tag>` where the volume was never created (minimal sequence: `run -d --name fz-<tag> alpine:3.20 sleep 300`, `volume rm fzv-<tag>`)
- Docker: exit 1, `Error response from daemon: get fzv-<tag>: no such volume`.
- Ferrocrate: exit 0, prints `volume rm: not found fzv-<tag>`. It reports the failure in the message but succeeds in the exit status.
- cause: the volume removal path treats "not found" as a removed state and returns success.
- scope: cleanup scripts that `volume rm` unconditionally never learn the volume was never there; `volume rm` after a failed create silently passes. Every rm-style verb should agree with Docker here (`network rm` and `rm` already error on missing).
- test: `volume rm` a name that was never created; assert exit 1 and stderr naming the volume.
