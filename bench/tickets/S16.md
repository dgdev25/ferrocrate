# S16 — build: COPY does not expand wildcards
- source: real-app bench · app: node-getting-started · step: build · class: product · status: closed · first seen: 2026-08-26
- command: `COPY package*.json ./`
- Docker: copies every match. Ferrocrate: `invalid Dockerfile: COPY source /data/dev/bench-apps/node-getting-started/package*.json is unavailable: No such file or directory`.
- impact: `COPY package*.json ./` is the standard first line of almost every Node Dockerfile; the same pattern appears in Python (`requirements*.txt`) and Go builds.
- fix: expand shell-style globs in COPY and ADD source arguments against the build context, as Docker does; an empty match is an error, matching Docker's behaviour. Regression test: a context with two matching files and one non-matching, asserting exactly the matches arrive.

## Verification
Verified 2026-08-27 against the fourteen-application bench. COPY glob expansion works; the build step passes on 7 of 9 applications that reach it, and no failure now mentions an unavailable glob source.
Gate: docker-client conformance 85/85 in BuildKit-default and classic modes, cargo test --workspace green.
