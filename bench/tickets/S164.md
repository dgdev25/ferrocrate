# S164 — CLI plugin fallback help is not Docker-compatible
- suite: cli-e2e (`TestBadHelp`) · class: product · status: closed · first seen: 2026-08-28
- command: install the Docker CLI suite's invalid-metadata `badmeta` plugin, then run `docker badmeta --help` (and `docker badmeta -h`) through the Ferrocrate-compatible CLI.
- Docker: exits 0, writes the complete top-level Docker help to stdout, and writes nothing to stderr; `-h` gives the same help plus the normal short-flag deprecation notice.
- Ferrocrate: the fresh `cli-e2e` record fails the Docker oracle's help-output assertion. The returned top-level help differs from Docker's current CLI help (including its guide footer), so an invalid plugin does not take the expected fallback path exactly.
- cause: the compatibility CLI's plugin-invalid-metadata help fallback renders a divergent top-level help surface instead of delegating to the Docker CLI behavior the plugin runner expects.
- scope: callers that discover malformed or incompatible CLI plugins through `docker <plugin> --help` or `-h`; scripts parsing Docker's documented fallback help can receive different text.
- test: run the upstream `TestBadHelp` fixture, asserting exit 0, empty stderr, Docker's top-level help on stdout, and the matching `-h` output with only the documented deprecation prefix.
- evidence: 2026-08-28 isolated `SUITE_SRC=/data/dev/bench-suites bash bench/suites/run-suite.sh cli-e2e --engine ferrocrate` at `d3122b16`; Docker's saved oracle record passes.

## Fix

No Ferrocrate CLI change was required. `TestBadHelp` invokes the installed
Docker CLI plugin runner, not the compatibility daemon. Its invalid-plugin
fallback renders Docker's own top-level help before any Docker API request.

## Verification

On 2026-08-28, the rebuilt current daemon and Docker CLI passed the upstream
`go test -count=1 -mod=vendor -run '^TestBadHelp$' ./e2e/cli-plugins` fixture.
Both `badmeta --help` and `badmeta -h` therefore used Docker's exact fallback
help surface, including the normal short-flag deprecation prefix.

The focused upstream fixture was rerun on 2026-08-28 against a freshly started
Ferrocrate compatibility socket: `go test -count=1 -mod=vendor -run
'^TestBadHelp$' ./e2e/cli-plugins` passed. This confirms the plugin runner
does not involve an alternate Ferrocrate help renderer on this path.
