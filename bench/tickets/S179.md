# S179 — provider service output is not surfaced in `compose up` output

- suite: compose-e2e · class: product defect · status: closed (d0e2d10e; retested 2026-08-29) · first seen: 2026-08-28
- command: `docker compose up` with a provider-type service whose example provider prints `CLOUD_REGION=us-east-1` (TestProviderRawSetEnvOverridesUserEnv, TestProviderRawSetEnvOverridesInheritedEnvMapForm)
- Docker: the provider's stdout lines appear in the `up` output; the test asserts output contains `test-1  | CLOUD_REGION=us-east-1`.
- Ferrocrate: the line never appears; the run artifacts show the provider's environment captured into logs but not streamed as service output.
- impact: 2 failures.
- regression tests: an integration test wiring the repo's `bin/build/example-provider` and asserting its output line appears in `up` stdout.

Fix: the streamed provider output itself was already correct at the retest base — `test-1  | CLOUD_REGION=us-east-1`, the absence of `user-defined-region` and the `overrides environment variable` warning all matched Docker on 2026-08-28's later commits. What still failed the two upstream tests was termination: compose's monitor only drops a service from its watched set on the `die` event, and the daemon answered `GET /events` only after the in-flight `POST /containers/{id}/start` released the container-store guard (~350 ms on this daemon). The container exited inside that window, the follower seeded its cursor past the `die`, and `compose up` hung; `docker events` proved the `die` carried name and labels and was journaled 4.5 ms before the follower subscribed. `/events` now skips the container-store guard (it reads the event journal under its own lock), so the subscription is seeded at connect time. Retest 2026-08-29 at `d0e2d10e`: all three provider scenarios (`user-env`, `inherited`, `inherited map form`) exit 0 in ~2 s with the `test-1  | CLOUD_REGION=us-east-1` line and the override warning, matching Docker; upstream `TestConvertAndTransformList`, `TestProviderRawSetEnvOverridesUserEnv`, `TestProviderRawSetEnvOverridesInheritedEnv` and `TestProviderRawSetEnvOverridesInheritedEnvMapForm` pass 3/3 runs. Regression tests: `docker_request_needs_store_guard` exempts `GET /events` from the store guard, and `docker_compat_event_follower_subscribed_before_start_sees_the_whole_lifecycle` asserts a follower subscribed before a container starts sees that container's whole lifecycle.
