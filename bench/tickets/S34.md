# S34 — daemon: no POST /grpc hijack route, so BuildKit cannot attach through the Docker API socket
- suite: buildkit-dockerfile (1015 of 1017 recorded integration tests fail on it) · class: product · status: open · first seen: 2026-08-27
- command: `POST /grpc` with `Upgrade: h2c` against the Docker-compat socket, then an HTTP/2 client preface on the hijacked connection.
- Docker: `101 Switching Protocols` with `Upgrade: h2c`, then the embedded BuildKit gRPC server sends its HTTP/2 SETTINGS frame (verified 2026-08-27 with a raw-socket probe against the oracle: first bytes after the preface are an HTTP/2 SETTINGS frame).
- Ferrocrate: `404 {"message":"not found"}`. Verified with the same probe against release-artifacts/ferro-cli.
- cause: BuildKit's docker-driver path — used by buildx and by BuildKit's own integration harness — proxies the control gRPC API over a hijacked `POST /grpc` connection (`DialHijack(ctx, "/grpc", "h2c", nil)` in util/testutil/workers/dockerd.go, the same call the moby client's `Client.DialHijack` makes for the docker-container driver). With 404 the hijack never upgrades, the worker proxy has no connection to pump, and the gRPC client blocks until its 20 s context deadline: `error reading server preface: raw-read unix @->/tmp/buildkit-integration…: use of closed network connection`, surfacing as `failed to list workers` / `listing workers for Build`. Every test in the suite that needs a worker fails identically; the suite's 45 m budget then runs out before the tail of the matrix is recorded.
- scope: a `POST /grpc` (and `POST /v1.xx/grpc`) route in the Docker-compat HTTP server that answers `101 Switching Protocols` on `Upgrade: h2c` and bridges the hijacked byte stream to the BuildKit gRPC service — the same surface real dockerd exposes when BuildKit is enabled. Without it every BuildKit client that talks to the Docker socket (buildx docker-driver, docker buildx, the bench's buildkit-dockerfile suite) cannot run a single solve.
- test: raw-socket probe — send `POST /grpc` with `Upgrade: h2c`, assert 101 with `Upgrade: h2c`; send the HTTP/2 client preface + empty SETTINGS, assert an HTTP/2 SETTINGS frame arrives within 1 s; then one `client.New(ctx, "unix://…")` + `ListWorkers` returns at least one worker.
- note: this run also proves S31's gate workaround (HEAD /_ping) is not sufficient on its own — the ping layer passes and the suite still dies one layer deeper at /grpc. The two tickets are independent routes.
