# S153 — compose: sequence-form `entrypoint` is rejected
- app: docker-flask · steps: `compose-up`, `compose-health`, `compose-ps`, `compose-logs`, `compose-down` · class: product · status: closed (694ee733) · first seen: 2026-08-28
- command: `cd /data/dev/bench-apps/docker-flask && ferro-cli compose up -d`.
- Docker: accepts the worker service's list-form `entrypoint` and starts the Compose project.
- Ferrocrate: exits 1 with `compose parse error: services.worker.entrypoint: invalid type: sequence, expected a string at line 94 column 17`.
- cause: the Compose model accepts only a scalar command for `entrypoint`, while Compose permits both a shell-form string and an exec-form sequence.
- scope: every Compose service using the documented list form; S91 fixed scalar `healthcheck.test`, but not this distinct string-or-sequence field.
- test: parse and run a fixture with `entrypoint: ["/bin/sh", "-c", "echo ok"]`; retain scalar entrypoint coverage and assert both normalize to Docker-compatible execution.
- proof: current-main 14-app matrix with `FERROCRATE_BIN=/data/dev/ferrocrate-app-retriage2/target/release/ferro-cli`, `bench/results/2026-08-28/docker-flask-ferrocrate.jsonl`.

## Fix
`Service.entrypoint` now accepts both Compose forms and normalizes each to launcher argv. The shared Compose image-execution resolver consumes that argv directly, preserving exec-form arguments rather than reparsing them as a shell string.

## Verification
Focused regressions passed in the isolated runtime: `parses_scalar_and_list_entrypoints_as_execution_arguments` verifies both YAML forms normalize to the same argv; `compose_exec_form_entrypoint_preserves_each_argument` verifies an exec-form argument containing spaces remains one argument when combined with the image command.
