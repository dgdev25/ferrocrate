# S189 — compose: only the first port-publishing service in a project starts; the rest fail "publish requires --network bridge"

- apps: any Compose project with more than one service that publishes a port and no explicit `networks:` block (found via cession, a real external repo, not the bench matrix) · step: compose up · class: product · status: open · first seen: 2026-08-28
- command: a `docker-compose.yml` with 2+ services each declaring `ports: ["<host>:<container>"]` and no custom network, then `ferro-cli compose up -d`.
- Docker: every service with a published port starts and is reachable on its host port; Compose's implicit default network is a bridge network shared by all services.
- Ferrocrate: only the first service to start (the rootless "network leader" for the project's implicit network) succeeds. Every other service that also publishes a port fails with `run: publish requires --network bridge`, even though it correctly joined the same shared bridge network as the leader.
- cause: `compose_rootless_network_binding` (ferro-cli/src/main.rs) resolves a non-leader service's effective network mode to `container:pid:<leader_pid>` (correct — it's joining the leader's netns), but the publish guard at `run: publish requires --network bridge` (main.rs:6886) checks the raw resolved `effective_network` string literally equals `"bridge"`. A joined network is not literally the string `"bridge"` even though it is a bridge network by association, so the guard incorrectly rejects it.
- scope: any Compose project with 2+ port-publishing services and the default implicit network — a very common shape (most simple/medium Compose files don't declare custom networks). With N such services, N-1 of them silently fail to start.
- test: a 3-service Compose file (no custom network) where each service publishes a distinct host port; `compose up -d`; assert all three containers reach `running` and are reachable on their respective host ports, not just the first one started.
- evidence: found 2026-08-28 during a real-world pilot test (cession, `/data/dev/ferrotest/cession`, copied from a real external repo, not part of the bench matrix). Reproduced with a 3-service compose file (postgres, gotenberg, mailpit): 1 of 3 started, the other 2 failed with the exact error above.
